# Feature Table

Generated by `src/features/build_features.py`. 963,072 rows, one per well-quarter reading.

## Column reference

| Feature | What it is | EDA finding it's based on |
|---|---|---|
| `season` | Measurement quarter (Jan/May/Aug/Nov) | Seasonality |
| `depth_same_quarter_last_year` | Same well's reading exactly 1 year earlier | Seasonality |
| `depth_last_reading` | Same well's immediately previous reading | Baseline signal |
| `rolling_mean_4` | Mean of the well's last 4 readings (excl. current) | Baseline signal |
| `long_term_slope_m_per_year` | Well's trend (m/year) using only readings before this row | Depletion / early-warning signal |
| `site_type` | Dug/bore/tube well etc. | Site-type effects |
| `neighbor_mean_depth` | Mean depth among 5 nearest wells, same date | Spatial patterns |
| `district`, `state` | Administrative region | Spatial patterns / output granularity |
| `n_prior_readings` | How many readings this well had before this one | Confidence / coverage |

## Missingness (fraction of rows with a real value)

| Feature | Coverage |
|---|---|
| `depth_last_reading` | 97.1% |
| `depth_same_quarter_last_year` | 80.1% |
| `rolling_mean_4` | 97.1% |
| `long_term_slope_m_per_year` | 91.5% |
| `neighbor_mean_depth` | 92.1% |

`depth_same_quarter_last_year` is missing whenever a well doesn't have a reading exactly 1 year before the current one (gaps in monitoring); `long_term_slope_m_per_year` is missing whenever a row has fewer than 3 prior readings for that well to fit a trend from yet.

`depth_last_reading` and `rolling_mean_4` should always have *identical* coverage, and it should be below 100%: both look only at readings before the current row, so both are missing on exactly one row per well -- its first. That equality is a cheap integrity check on this table, and it did not always hold. `rolling_mean_4` used to report 100% coverage, which is impossible for a feature that excludes the current reading; the cause was a window that rolled across well boundaries, so each well's first rows averaged the *previous* well's readings. See the note below and `tests/test_features.py`.

## Note: two data-leakage bugs this table used to have

Both were found and fixed before any model was trained on it, and both are now pinned by `tests/test_features.py`. The first was `rolling_mean_4` rolling across well boundaries (above); the second is below.

## Note: `long_term_slope_m_per_year` is an expanding-window feature

Each row's value is fit using only that well's readings strictly BEFORE that row's own date -- never the row's own reading or any later one. This makes it safe to use as a training feature (no look-ahead). An earlier version of this script computed one full-history slope per well and copied it onto every row for that well, which *was* look-ahead bias (rows near the start of a well's record would have `seen` its future decline). That bug was caught and fixed before any model was trained on this table -- worth knowing about since it's the kind of mistake that silently inflates offline accuracy without showing up until deployment.
