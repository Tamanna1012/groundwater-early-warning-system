# Feature Table

Generated by `src/features/build_features.py`. 963,072 rows, one per well-quarter reading.

## Column reference

| Feature | What it is | EDA finding it's based on |
|---|---|---|
| `season` | Measurement quarter (Jan/May/Aug/Nov) | Seasonality |
| `depth_same_quarter_last_year` | Same well's reading exactly 1 year earlier | Seasonality |
| `depth_last_reading` | Same well's immediately previous reading | Baseline signal |
| `rolling_mean_4` | Mean of the well's last 4 readings (excl. current) | Baseline signal |
| `long_term_slope_m_per_year` | Well's full-history linear trend | Depletion / early-warning signal |
| `site_type` | Dug/bore/tube well etc. | Site-type effects |
| `neighbor_mean_depth` | Mean depth among 5 nearest wells, same date | Spatial patterns |
| `district`, `state` | Administrative region | Spatial patterns / output granularity |
| `n_prior_readings` | How many readings this well had before this one | Confidence / coverage |

`depth_same_quarter_last_year` is missing whenever a well doesn't have a reading exactly 1 year before the current one (gaps in monitoring); `long_term_slope_m_per_year` is missing for wells with fewer than 3 distinct dates in their whole history.

## Important caveat: look-ahead bias in `long_term_slope_m_per_year`

This feature is computed once per well from **that well's entire history**, including readings that come after many of the rows it's attached to. That makes it useful as a *current well profile* (e.g. for ranking wells/districts by risk today), but it is look-ahead bias if used to train a model to predict individual historical rows -- the model would effectively see the future. Before this feature table is used for baseline or ML forecasting (the next pipeline stage), this column must be replaced with an expanding-window version that only uses data available up to each row's own date.
